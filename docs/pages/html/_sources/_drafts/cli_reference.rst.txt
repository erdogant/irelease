Module Overview
---------------

The :mod:`clizard_main` module acts as a thin, automatically generated façade around the core release logic encapsulated in :func:`irelease.main`. By leveraging **Clizard**, it translates user intent expressed on the shell into concrete calls to the underlying API without any hand‑crafted argument parsing. This design choice removes the need for repetitive boilerplate and guarantees that any change to the public interface of :mod:`irelease` is reflected instantly in the command line experience.

A key feature of this module is its ability to load cosmetic overrides from a ``.clizard`` configuration file located at the repository root (``REPO_PATH``). These overrides are merged with hard‑coded defaults for settings, argument metadata, call style and tips. The merging logic ensures that developers can customize the look and feel of the CLI while still benefiting from sensible defaults that keep the tool usable out of the box.

Two public functions expose the functionality: :func:`build_cli`, which constructs a fully configured :class:`~clizard.GenericCLI` instance, and :func:`main`, which serves as the console‑script entry point. The module is auto‑generated by Clizard; any manual changes should be performed via ``clizard --scaffold`` to preserve consistency across releases.

.. code-block:: python

   from clizard_main import build_cli
   cli = build_cli()
   cli.run()

build_cli
---------

The :func:`build_cli` function is responsible for creating a :class:`~clizard.GenericCLI` instance that is pre‑configured for the Interactive Release Tool. It begins by loading cosmetic overrides through ``load_clizard_file(REPO_PATH)``, which returns a configuration object containing user‑specified settings, argument metadata and call style preferences. These values are then merged with the module’s hard‑coded defaults: ``_DEFAULT_SETTINGS``, ``_DEFAULT_ARG_META`` and ``_DEFAULT_CALL_STYLE``. The resulting configuration drives the construction of the CLI instance.

Once the :class:`~clizard.GenericCLI` object is instantiated, a special ``/run`` command is registered. This handler acts as a bridge between the user‑supplied arguments and the original :func:`irelease.main`. Depending on the chosen call style, it either reconstructs ``sys.argv`` to mimic a traditional CLI invocation or builds a keyword argument dictionary that is passed directly to :func:`irelease.main`. After execution, any non‑None result is printed to the console, providing immediate feedback to the user.

The design of this function emphasizes flexibility and maintainability. By centralizing configuration merging in one place, it becomes trivial to add new cosmetic options or adjust defaults without touching the command registration logic. Moreover, the use of Clizard’s declarative API means that adding new commands or altering existing ones can be achieved through simple decorator syntax rather than low‑level argument parsing code.

.. code-block:: python

   from clizard_main import load_clizard_file
   from clizard import GenericCLI

   # Load user overrides
   clz = load_clizard_file(REPO_PATH)

   # Merge with defaults and construct CLI
   cli = GenericCLI(
       settings=clz.settings,
       arg_meta=clz.arg_meta,
       call_style=clz.call_style,
       tips=clz.tips

main
----

The :func:`main` function serves as the console‑script hook that users invoke when they execute ``irelease`` from the command line. Its sole responsibility is to instantiate the CLI via :func:`build_cli` and delegate all parsing, dispatching and output handling to the constructed :class:`~clizard.GenericCLI` object. Because Clizard manages the entire execution flow, :func:`main` remains intentionally lightweight and devoid of any parameters or return values.

This minimal entry point pattern is common in Python CLI projects that rely on external frameworks. It keeps the public API clean while still allowing developers to customize the underlying CLI by modifying the autogenerated module or providing additional configuration files. The design also ensures that the tool can be invoked both as a script and as an imported module without side effects.

.. code-block:: python

   def main():
       build_cli().run()

Important Notes
---------------

* Auto‑generated by Clizard; regenerate with ``clizard --scaffold``.
* Loads ``.clizard`` config from ``REPO_PATH`` for cosmetic overrides.
* Merges hardcoded defaults: ``_DEFAULT_SETTINGS``, ``_DEFAULT_ARG_META``,
  ``_DEFAULT_CALL_STYLE`` and ``_DEFAULT_TIPS``.
* Exposes :func:`build_cli()` to construct the CLI instance and
  :func:`main()` as the entry point.
* The ``/run`` command supports both argv‑style (reconstructs ``sys.argv``)
  and kwargs‑style invocation.
