Release and Deployment

Automated Release Workflow

The automated release pipeline orchestrated by the irelease utilities is designed to streamline the process of publishing a new version of a Python package both to GitHub and PyPI with minimal manual intervention. At its core, the workflow first retrieves PyPI credentials from a .pypirc file, then builds a Bash wrapper script (release.sh) that forwards all arguments to the underlying Python logic. This separation allows developers to invoke releases from any environment where Bash is available while keeping the heavy lifting in pure Python.

Once the wrapper is in place, the run() function performs the core build-and-publish routine. It determines the next semantic version based on the current tag or commit history, updates the package metadata, builds both source distributions and wheels using setuptools, optionally cleans stale artifacts, installs any declared dependencies, and finally uploads the resulting packages to PyPI via twine. The main() entry point is exposed through a CLI generated by clizard, enabling interactive or scriptable invocation of the entire workflow with a single /run command.

The integration with clizard’s build_cli() function ensures that any configuration overrides defined in .clizard are merged with defaults before dispatching to irelease.main(). This design choice gives developers a friendly prompt while still allowing fully automated, headless execution when needed. The result is a repeatable, auditable release process that reduces the risk of human error and speeds up time-to-market.

Parameters for run

Name

Type

Description

user

str

PyPI username to use when uploading packages.

project

str

Name of the Python package/project being released.

clean

bool

If True, removes existing build artifacts before creating new ones.

install

bool

Installs any dependencies required for building or testing the package.

twine

str or None

Path to a custom twine executable; if None the system default is used.

verbose

int

Controls diagnostic output level during the build and upload process.

–help

flag

When present, displays available options and arguments instead of executing the workflow.
Running a full release
from irelease import run
run(user="myuser",
    project="mypackage",
    clean=True,
    install=True,
    twine=None,
    verbose=1)

from irelease import main

main(args=args)

The workflow’s design emphasizes transparency and control. By exposing each step as a callable function, developers can embed the release logic into custom scripts or CI pipelines while still benefiting from clizard’s interactive prompt for ad‑hoc releases. The separation between credential retrieval, script generation, execution, and CLI exposure ensures that each concern is isolated, testable, and maintainable.
