Module Overview

The clizard_main module acts as a thin, automatically generated façade around the core release logic encapsulated in irelease.main(). By leveraging Clizard, it translates user intent expressed on the shell into concrete calls to the underlying API without any hand‑crafted argument parsing. This design choice removes the need for repetitive boilerplate and guarantees that any change to the public interface of irelease is reflected instantly in the command line experience.

A key feature of this module is its ability to load cosmetic overrides from a .clizard configuration file located at the repository root (REPO_PATH). These overrides are merged with hard‑coded defaults for settings, argument metadata, call style and tips. The merging logic ensures that developers can customize the look and feel of the CLI while still benefiting from sensible defaults that keep the tool usable out of the box.

Two public functions expose the functionality: build_cli(), which constructs a fully configured GenericCLI instance, and main(), which serves as the console‑script entry point. The module is auto‑generated by Clizard; any manual changes should be performed via clizard --scaffold to preserve consistency across releases.

from clizard_main import build_cli
cli = build_cli()
cli.run()

build_cli

The build_cli() function is responsible for creating a GenericCLI instance that is pre‑configured for the Interactive Release Tool. It begins by loading cosmetic overrides through load_clizard_file(REPO_PATH), which returns a configuration object containing user‑specified settings, argument metadata and call style preferences. These values are then merged with the module’s hard‑coded defaults: _DEFAULT_SETTINGS, _DEFAULT_ARG_META and _DEFAULT_CALL_STYLE. The resulting configuration drives the construction of the CLI instance.

Once the GenericCLI object is instantiated, a special /run command is registered. This handler acts as a bridge between the user‑supplied arguments and the original irelease.main(). Depending on the chosen call style, it either reconstructs sys.argv to mimic a traditional CLI invocation or builds a keyword argument dictionary that is passed directly to irelease.main(). After execution, any non‑None result is printed to the console, providing immediate feedback to the user.

The design of this function emphasizes flexibility and maintainability. By centralizing configuration merging in one place, it becomes trivial to add new cosmetic options or adjust defaults without touching the command registration logic. Moreover, the use of Clizard’s declarative API means that adding new commands or altering existing ones can be achieved through simple decorator syntax rather than low‑level argument parsing code.

    arg_meta=clz.arg_meta,
    call_style=clz.call_style,
    tips=clz.tips
)

main

The main() function serves as the console‑script hook that users invoke when they execute irelease from the command line. Its sole responsibility is to instantiate the CLI via build_cli() and delegate all parsing, dispatching and output handling to the constructed GenericCLI object. Because Clizard manages the entire execution flow, main() remains intentionally lightweight and devoid of any parameters or return values.

This minimal entry point pattern is common in Python CLI projects that rely on external frameworks. It keeps the public API clean while still allowing developers to customize the underlying CLI by modifying the autogenerated module or providing additional configuration files. The design also ensures that the tool can be invoked both as a script and as an imported module without side effects.

def main():
    build_cli().run()

Important Notes

  • Auto‑generated by Clizard; regenerate with clizard --scaffold.

  • Loads .clizard config from REPO_PATH for cosmetic overrides.

  • Merges hardcoded defaults: _DEFAULT_SETTINGS, _DEFAULT_ARG_META, _DEFAULT_CALL_STYLE and _DEFAULT_TIPS.

  • Exposes build_cli() to construct the CLI instance and main() as the entry point.

  • The /run command supports both argv‑style (reconstructs sys.argv) and kwargs‑style invocation.
